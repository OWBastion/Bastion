# 性能深度优化方案

## 目标与边界

本计划针对服务器高负载和炸房风险，聚焦技能特殊效果调度、数组访问、AI 目标查询与临时对象生命周期。

- 不重新启用 Anti Crash。持续调用 `getAverageServerLoad()` 的检测规则已在实际运行中证明会增加负担，不能作为运行时保护手段。
- 本文的“特效”指技能特殊效果，包括附加伤害、状态、DOT/HOT、生命池、位移、属性与冷却变化；视觉实体仅是其中需要管理生命周期的一类表现。
- Workshop 子程序按顺序执行。优化重点是规则触发频率、数组重建、事件链和生命周期边界，而不是为假设的子程序并发增加锁。
- 第一阶段必须保持玩法语义：不改变伤害、范围、触发频率、目标规则或玩家手感；涉及这些变化的措施只能进入第二阶段并独立验证。
- 不重排入口 include 流程，不重编号全局或玩家变量，且 `src/main.opy` 与 `src/devMain.opy` 必须继续通过相同的共享实现保持一致。

## 当前基线

以 `pnpm run tools -- perf:scan --strict` 为基线：

| 风险级别 | 数量 | 说明 |
| --- | ---: | --- |
| HIGH | 0 | 没有发现无等待循环风险。 |
| MEDIUM | 4 | 均为持续规则中距离/范围查询先于廉价门控的条件排序问题。 |
| LOW | 89 | 主要是距离、玩家集合扫描、排序和链式数组操作；它们是审计候选项，不要求机械归零。 |

当前 MEDIUM 项位于 `src/bastion/init.opy` 与 `src/effects/init.opy`。第一阶段完成后应保持 `HIGH=0`，并清除这四项 MEDIUM；LOW 项按启动路径、低频路径与热路径分类后再决定处理顺序。

## 优化原则

### 数组与状态

- 固定、按 ID 对齐的状态适合常数时间的激活、冷却和累计值查询；动态数组只保存当前启用的目标、句柄或短期队列，且必须有上限和清空边界。
- 热路径应先以当前事件身份或廉价激活状态粗门控，再读取少量运行槽位；不要在每次伤害、治疗或持续规则评估时扫描完整能力池或重建相同玩家集合。
- 同一 tick 中需要重复使用的范围目标应只计算一次。缓存的目标、位置、原始伤害和攻击者必须在延迟前取得，并在事件结束、死亡、换英雄、重置和离场时失效。
- 统计值、冷却值、目标集合与资源句柄的生命周期不同；在 Bastion 源码中保持这些状态的责任边界，避免把数值、玩家、HUD 和 Effect 句柄混作同一临时状态。

### 技能特殊效果

- 将概率绑定到离散游戏事件或明确的状态边沿，而不是持续成立的条件；一次技能使用、一次命中、一次治疗或一次冷却进入都只能得到一次判定机会。
- 可重复触发的冷却优先保存“下次可触发时间”，而非为每次触发创建等待至解锁的规则实例；这样既能直接判断剩余时间，也不会留下旧实例。
- 短时属性、状态和生命池效果采用“写入来源层 → 统一刷新 → 到期清空来源层”的模型。事件主体加成与事件内部短时 Proc 必须能够分别清理，不能依赖对当前最终值做反向增减。
- 事件核心是最终清理的唯一所有者。带 `wait` 的规则只能在其启动事件实例仍有效时结束自身的局部工作；不得在旧事件已被替换后清理新事件的属性、目标或资源。
- 事件附加伤害、DOT、反伤和处决必须明确其触发来源与是否可再次触发同类 Proc。第一阶段先记录并保护既有语义，只有在实测证明伤害链为瓶颈时才在第二阶段调整允许的链路或目标数。

### 视觉反馈与持续对象

- 固定信息面板和重复出现的事件提示使用固定 HUD 槽位更新文本，不随轮次或每次 Proc 新增 HUD。
- 玩家附着型持续 VFX 应在事件开始时创建一次，随后仅重评估可见性、位置或强度，并由事件核心统一销毁；爆炸、命中闪光和短促音效等一次性反馈不保存长期句柄。
- 每个视觉反馈都应声明受众：本人、攻击者与受害者、附近相关玩家、队伍或全体玩家。局部战斗反馈默认不广播给 `getAllPlayers()`；全局可见性必须是玩法或信息设计的明确需求。
- 将机制结算与视觉演出分层。高负载时可以先裁减纯装饰性的循环粒子、投射物轨迹或重复音效，保留伤害、状态、冷却和关键预警；不得用持续服务器负载采样驱动这项降级。

## 第一阶段：行为等价优化

### 1. 规则节拍与条件门控

- 从热路径移除以服务器负载读数计算的循环等待，改为命名的固定节拍常量；节拍以当前正常负载下的行为为基准。
- 保留启动错峰：多玩家或多 Bot 的初始化、扫描与批量操作按 slot 或小范围随机延迟分散到不同 tick。
- 修复已报告的条件顺序：先放置事件类型、存活、生成完成、状态开关、按键等廉价且高选择性的判断；距离、视线、半径、数组扫描和排序必须在后。
- 仅在确实需要手动控制检查频率的非帧关键逻辑中，将昂贵检查移入 `If` 加固定 `wait` 的循环；其余持续规则仍优先使用 `@Condition` 门控。

### 2. Bastion AI 目标路径

- 将目标获取维持为四段固定流程：已有目标快速有效性检查、一次候选集生成、候选 LoS 过滤、单次排序选择。
- 每轮目标获取只构建一次候选数组；条件、行动、预瞄和后续瞄准不得重新扫描相同玩家集合。
- 保留现有 `bastionBotTargetPrefer` 的目标优先级和选择语义；不以性能优化为由改写偏好逻辑。
- 对无目标扫描、预瞄、瞄准点刷新和转向刷新使用固定节拍与错峰，避免多个 Bot 在同一 tick 进行距离、LoS 或排序计算。
- 若一次候选扫描需要处理多个玩家，优先使用 Workshop 内建数组操作；只有超出已知小上限的迭代才以有界 `for` 循环分帧批处理。

### 3. 事件效果与数组

- 静态配置数组、固定状态数组、短期队列与临时计算数组保持分层；不新增混合 HUD、目标、计时、句柄和临时计算用途的大型状态数组。
- 当前事件的运行状态按用途拆分为身份、短时修正、冷却/计数、目标缓存和资源句柄；固定槽位只承载同一种生命周期的数据。
- `getLivingPlayers`、范围查询、`filter`、`sorted`、`map` 仅在低频循环或一次性触发动作中执行，禁止将大数组或复杂玩家集合直接放入高频持续规则条件。
- 每次事件激活只计算并缓存一次目标集合；循环体复用缓存，并在效果结束、死亡、换英雄、重置和离场时清空。
- 动态数组必须拥有明确上限：目标列表、叠层、生命池句柄、HUD 句柄和临时效果句柄到达上限后不再写入或创建。
- 伤害事件的多目标语义必须在 `wait` 前完成，或切换为按受害者处理、显式缓存目标集合并有界遍历；不得依赖等待后的事件上下文代表所有原始目标。
- 伤害、治疗、按键和技能相关的概率 Proc 只在离散触发或状态边沿判定一次；不得由“仍在冷却”“仍在受伤”等持续条件重复抽样。
- 冷却以时间戳保存下次可触发时间。需要短时效果时，保存过期时间并由单一管理路径清空，不为每次触发叠加独立的延迟回滚实例。

### 4. 持续对象生命周期

- 技能本体优先使用 Workshop 原生状态、属性、DOT/HOT 和生命池；不为纯数值效果新增持续视觉实体。
- 持续视觉对象采用“首次创建、状态控制可见性/位置、结束清理”的模式，复用已有句柄而非反复创建和销毁。
- 将一次性命中/爆炸反馈与持续 VFX 分开：前者即时播放且不登记长期句柄，后者必须登记到专属资源域；视觉对象的接收者按本人、相关玩家、附近玩家、队伍、全体玩家分级确定。
- 每一种临时对象必须有唯一的状态与句柄归属，并覆盖效果结束、玩家死亡、英雄切换、全局重置和玩家离场五个清理边界。事件核心是唯一最终清理所有者；延迟规则结束前必须确认其仍属于启动时的事件实例。
- 短时属性或状态效果写入独立的临时来源层，到期只清空该层并统一重算；不得通过“加值 → `wait` → 减去当前值”回滚，以免旧实例污染替换后的事件。
- HUD 使用固定槽位复用；禁止随着事件轮次或重复触发无限追加 HUD 句柄。

## 第二阶段：实测后才允许的调参

只有在第一阶段完成后，实机验证仍证明原生投射物、碰撞爆炸或伤害链是主要瓶颈时，才启动本阶段。

- 为 Bastion 副火力脉冲间隔、Nano 副火力触发间隔和高频范围伤害单次目标数提供独立、命名、默认关闭的配置项。
- 每项调参单独提交、独立回归，可立即恢复为第一阶段行为；不得与结构优化混入同一变更。
- 优先控制“投射物创建频率 × Bot 数量”与“伤害事件频率 × 范围目标数”的乘积，不新增服务器负载采样规则。
- 每项调参必须记录对 DPS、命中频率、目标覆盖和玩家体感的影响，并在最大支持人数/Bot 配置下复测。

## 验证矩阵

| 层级 | 验证 | 通过标准 |
| --- | --- | --- |
| 静态 | `pnpm run tools -- perf:scan --strict` | HIGH 保持为 0，MEDIUM 从 4 降为 0。 |
| 编译 | `pnpm run build:main`、`pnpm run build:dev` | 两个入口均能编译。 |
| 工具 | `pnpm run tools:test` | 工具测试通过；修改事件数据时追加相关事件同步测试。 |
| 文本 | `./tools/check_locale_keys.sh` | 仅在修改源文本或本地化时运行并通过。 |
| 生命周期 | 事件正常结束、中途死亡、换英雄、进度重置、强制替换、离场后重连 | 旧实例不能清理新事件；属性、状态、目标缓存、VFX 与生命池均无残留。 |
| Proc | 高频命中/治疗、DOT、反伤和附加伤害组合 | 概率每个离散触发只结算一次；冷却、链路与统计保持既有语义。 |
| 视觉 | 多玩家同时事件、局部战斗与全局机制 | HUD 固定复用；持续 VFX 不重复创建；局部反馈只发送给设计规定的受众。 |
| 实机 | 非练习靶场、最大支持玩家与 Bot 配置 | 目标获取、副火力、Nano、范围事件、重置与离场均无行为回归、残留句柄或崩房。 |
| 长局 | 连续多轮事件与高频战斗组合 | 数组、HUD、效果和生命池句柄不累积；没有逐轮恶化的负载或状态残留。 |

## 执行顺序

1. 先修复四项 MEDIUM 条件排序并固化固定节拍/错峰规范。
2. 审计 Bastion AI 热路径，消除同轮重复扫描并保持目标选择语义。
3. 按事件逐个处理高频数组扫描、缓存、离散 Proc 与时间戳冷却，每个独立行为域单独验证。
4. 完成临时属性、事件实例与资源生命周期审计，优先处理可跨死亡、重置、替换或离场残留的状态和句柄。
5. 按固定 HUD、持续 VFX 复用和可见性分级审计视觉反馈；先降低纯装饰性成本，不改变机制结算。
6. 在第一阶段实机回归后，才决定是否开启第二阶段的投射物或范围调参。
